# 12. 데모 시나리오 6종 기대 결과 (11/11)

영상·리허설 때 "언제 무엇이 나와야 맞는지" 대조하는 표다. 5번 화면 검증과 영상 콘티에 쓴다.

**어떻게 만들었나**
- `data/scenarios-demo/*.json`(main `82f8876`)을 2번 엔진(11/10·11/11 고침 포함) → 연결기 → **1번 `PolicyInterventionManager`(실제 코드)**로 1배속 재생했다.
- 음성·내비·통풍은 정해 둔 대로 대답하는 가짜 실행기다: 질문이 시작되고 5초 뒤 대답(정상 0.8 s, drowsy만 첫 두 번 2.3 s·2.6 s 느림), 경유지 질문은 '응', 통풍 사전 동의 켬, 쉼터 찾기는 '없음'(지금 데이터엔 위치가 없어서).
- 연결기 `epochOffsetMs = startEpochMs`(데모 시작 시각)를 넣었다. 시각은 시나리오 시각이다(60배속이면 1분이 1초).
- 실제 앱에서는 3번 음성(대답 시간 판정)·4번 쉼터(위치) 결과에 따라 달라진다. 위 가정이 바뀌면 그 뒤 순서도 바뀐다.

## 3. 영상 장면에 맞추려면

- **시작 시각**: 연결기에 데모 시작 시각을 넣으면(11/10 고침) 14:00 시작 시나리오는 처음부터 취약 시간대라 1단계다. 0단계를 보이려면 취약 시간대(02~07시, 14~17시) 밖으로.
- **회전 지점 거리·실내 온도**: drowsy를 빼고 5개 파일에 없다. 없으면 첫 점수 5:40, 오늘의 나·출발 피로 20:10. 넣으면 1:10·15:10.
- **졸음 순서**: 지금은 17:30 급조향이 먼저 2단계를 불러, 기획서의 '추세형 64점 → 2단계'(시나리오 1의 23:10)보다 앞선다. 기획서 순서로 보이려면 첫 급조향을 추세형(21:10) 뒤로 옮긴다.
- **쉼터 이름·경유지·휴식 인증**: 시나리오에 `lat`·`lon`(고속도로 위를 움직이는 경로, 앞 40 km 안 졸음쉼터)과 쉼터 정차(P단 15분) 구간이 필요하다. 좌표는 4번 쉼터 표 `data/rest_areas/processed/rest_areas.csv`에서 고른다. 에뮬레이터 위치는 고정이라 진행 방향을 못 구한다.
- **시동 끔**: JSON `power` 칸(ON → OFF → ON)을 넣으면 꺼진 시간 처리를 보일 수 있다. 데모 '시동 끔' 버튼(DMO_005)은 아직 없다.
- **60배속**: 질문부터 대답 판정까지는 1배속(DMO_002). 2단계 → 1단계의 10분 기다림은 60배속이면 10초다.
