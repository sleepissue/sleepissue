# 제품 JSON 데모 직접 확인 순서

현재 소스 기준: [2026-11-12 변경과 검증](../devlog/2026-11-12-product-demo-usable.md).

**사용자 지시로 APK 생성·설치는 중단 중이다.** 아래 새 배속 선택과 첫 확인 예약은 소스/JVM 검증만 완료했고 기존 설치 앱에는 아직 반영되지 않았다. APK 작업 재개 요청 전까지 빌드·교체설치를 진행하지 않는다.

## APK 작업 재개 후 제품에서 확인할 순서

1. Virtual Console **P/속도0**, 기존 실제 감시·SDK 검증 중지를 확인한다. 실제 D단의 화면 제한을 우회하지 않는다.
2. 앱 홈의 **데모 → 시나리오 선택·재생**로 진입한다. 제품 데모 화면이며 개발 검증 화면의 ‘검증 예제 로드’와 다르다.
3. 기본 **JSON 구간**은 원본 속도를 보존한다. 짧은 기능 시연은 **10배 → 졸음**을 선택한다. 선택한 배속은 다음 시나리오를 누를 때 적용된다. 60배는 기존 성능 미달이 남은 시험용이다.
4. `PLAYING`, **데모 재생 중**, 시나리오 시간·원본 수·DEMO 출처·판단 결과 증가를 확인한다. 졸음 원본은 JVM에서 기존 판단으로3단계에 도달했다. 기기에서도 같은 결과인지 따로 확인한다.
5. 질문이 실제 시작되면 **1배**를 확인하고 말로 응답한다. 정상 종료·취소·실패 뒤에는 선택 구간 배속으로 돌아와야 한다. 실제 질문 없이 버튼으로 단계·위험도를 강제로 넣지 않는다. 음성 불가 시 나타나는 대체 응답은 음성 성공으로 기록하지 않는다.
6. **일시정지 → 기다림 → 재개**: 시나리오 시간이 멈췄다가 이어져야 한다. 재생 종료 시 `COMPLETED`, 원본18,000개, Hub 입력null·음성/SDK 정리를 확인한다. 질문/일시정지가 없으면 전체10배 원본30분은 약3분이다.
7. **다른 시나리오**를 선택해 이전 세션이 섞이지 않는지 확인한다. 정상·대화는 위험0이어도 오후 취약 시간대 때문에1단계 안내가 있을 수 있다. ‘정상=무조건0단계’로 판정하지 않는다.

## 시동 끔 대체 시연

1. 재생이 끝나기 전에 **쉼터 P단 준비(모의)**를 누른다. 실제 쉼터 도착이 아닌 명시적 데모 입력이다.
2. **시동 끔(저장 후 앱 종료)**를 누른다. 데모 전용 저장본을 디스크에 저장한 후 앱이 종료돼야 한다.
3. 앱을 다시 열고 JSON 데모로 진입한다. 저장 ID·단계·기준선 참조·최근 누적과 시계+22분 결과를 확인한다.
4. 기존 감시/수동 Room DB를 초기화하지 않는다. 실제 차량 OFF→ON·STR 또는 엔진 학습 창 전체 복원 성공으로 기록하지 않는다.

이 경로는 기존 구현을 보존했으며 이번에는 기기에서 재실행하지 않았다.

## 출발 피로 첫 확인을 시연하려면

현재 원본은30분에 끝나고 첫 확인 예정은30분10.1초다. **현 원본만으로 그 예정 질문을 볼 수 없다.** 시나리오 담당이 예정 시각 이후 충분한 길이의 원본 관측과 필요한 평소 기준선 이력 조건을 제공해야 한다. 1번은 그 예정 시각을 그대로 전달·예약하고, 이미 시작한 주의 확인과 중복하지 않는다.

현재 엔진은 이 원본에서15분10.1초에 출발 피로를 판정하고 그15분 뒤를 첫 확인으로 예약한다. ‘출발 후15분에 질문’과 같은 조건으로 바꾸지 않는다. 원본 담당에게는 최소30분10.1초 이후의 유효 관측에 더해 실제 질문·응답과 결과 확인 여유도 요청한다.

엔진이 정한 시각을 앞당기거나 시나리오 끝값을 새 센서값으로 복제해서 완료 처리하지 않는다. 예정 시각의 연결·중복·취소·저장은 JVM에서 확인했고 실제 제품 음성 시연은 원본 조건 확보 후 검증한다.

## APK 없이 현재 PC에서 확인할 명령

```bash
cd /home/a/StudioProjects/sleepissue/src/android
JAVA_HOME=/home/a/.local/opt/android-studio/jbr ./gradlew :app:testDebugUnitTest
```

이 명령은 JVM 시험이며 APK를 만들거나 기기에 설치하지 않는다. 최종 앱461개 통과가 기준이다. 엔진351개는 같은 날 앞 작업의 실행 근거를 재사용했다. 전체 결과는 실행 기록과 XML 집계를 확인한다.
