## 직접 누를 버튼과 기대값

1. 기존 AVD·Console을 켜고 **AVD Enabled/DDS ONLINE, P, 속도0**을 확인한다. 감시가 켜져 있으면 기존 화면의 **감시 중지** 후 SDK 소유권 해제를 기다린다.
2. **Playground SDK 실시간 검증 → 차속 권한 → 연결**. 이는 Room을 열지 않는 독립 수집 화면이다. 신호별 READ/조회 성공을 기다린다.
3. **VENTILATION_LEVEL / CABIN_TEMP_C**에서 실제 값과 AVAILABLE을 확인한다. 10초 이상 조작 없이 기다려도 조회가 성공하면 확인 시각과 조회 수만 갱신된다. 콜백을 재조회 횟수만큼 늘려 표시하면 안 된다. 수신/원천 시각을 확인 시각으로 덮지 않는다.
4. Console **Seat Temperature V1/V3/Off**는 별도 `SEAT_TEMPERATURE:ROW_1_LEFT`의 -1/-3/0이다. 통풍1/3의 입력 버튼이 아니다. 실제 통풍0→1→0은 이번 공식 API fixture로 확인했고 제품 제어 버튼은 추가하지 않았다. **Temperature Set**을25로 바꿔도 CABIN_TEMP_C가 즉시25가 된다고 기대하지 않는다.
5. 기존 사용자 경로가 없을 때 시험용 경로의 **안내 시작**(또는 시작 카운트다운)을 확인하고 SDK 화면에서 **재연결**한다. 이번 공식 sample의 원시/Hub는60초·50m·TBT50m이며 `ROUTE_GUIDING + isRouting=false`가 함께 온다. 요청 반환만으로 안내 시작을 판정하지 않는다. 자신의 시험 경로에서만 **안내 종료**하고 세 값null을 확인한다. [검증한 버튼 순서·명시적 runner](../devlog/2026-11-09-role1-sig-input.md#⑤-직접-따라-할-버튼-순서와-기대값)를 따른다. 현재 실내온도 변경·이동 heading·실제 교차로 통과는 미검증이다.
6. **진단 저장** 완료 후 **중지**. 최종 값은 null, 수집/Hub 중지가 기대값이다. 발행 감사의 실제 emit 최대 간격/110ms 초과를 확인한다. 평균10Hz만으로 통과를 판단하지 않는다.
7. 운행 경계는 사용자 DB에서 초기화/시간 진행하지 않는다. 아래 격리된 Room runner를 사용한다. 화면/앱 종료를 시동 OFF로 간주하지 않는다.

```bash
# 이미 교체 설치한 debug/test APK에서 직접 실행. connectedDebugAndroidTest·앱 삭제는 사용하지 않는다.
adb shell am instrument --user 10 -w \
  -e class com.sleepissue.awakedrive.data.Role1BoundaryRoomTest \
  com.sleepissue.awakedrive.test/androidx.test.runner.AndroidJUnitRunner
```

위 runner는 메모리 Room만 연다. 실제 5분/15분/2시간/24시간을 기다리거나 사용자 DB를 지우지 않는다. SDK 입력 fixture는 명시적 `role1SdkFixtures=true`에서만 실행하며 debug에만 제어 권한이 있다. release 수집기는 통풍/내비 제어를 호출하지 않는다.
