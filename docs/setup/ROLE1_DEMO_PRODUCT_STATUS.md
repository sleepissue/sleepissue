## A. 데모 시연 기준으로 더 필요한 것

1. **5번 최신 제품 경로와 합치기.** PR20의 LiveDriveActivity/ProductDemoSession을 기준으로 대표 화면을 정하고, 로컬의 첫 확인 예약·시동 끔/복원·품질 계약을 이관한다. assets의 `<id>.json`과 `scenarios/<id>.json`, loader 메모리 개선, MonitoringPipeline/VoiceCheckPort API가 겹친다. 한쪽 파일로 덮어쓰지 않는다. 이 확인이 끝난 뒤에만 중복 제품 데모 화면을 제거한다.
2. **새 원본과 시간축 확인.** 로컬 원본은30분/18,000개다. 이 원본의 출발 피로 첫 확인은30분10.1초라 종료 뒤다. 최신main은45분10초/27,100개로 이미 연장됐으므로 원본을 다시 만들기보다 최신 원본을 통합해 확인한다. 2번 엔진의 절대 시각과5번 실행기의 상대 시각을 한 번만 변환하고, 첫 확인 예약이 실제 도달하는지 시험한다. 평소 기준선3회 사전조건도 별도다.
3. **시연 장면별로 끝까지 확인.** 정상/딴짓/졸음/대화/보조 주행/출발 피로마다 어떤 입력으로 어떤 결과를 보여줄지 고정한다. 판단 점수·단계를 화면 버튼으로 주입한 시험과 원본 신호 기반 시연을 구분한다. 실제 질문→1배→응답/무응답→복귀, 휴식 안내·경유지 취소, 정차·인증/회복 결과를 확인한다. 실제 내비를 변경하지 않는 로컬 데모 모드와 실제 내비 실행을 연결한5번 모드의 차이를 명시한다.
4. **시동 끔/다시 켜기 장면 확인.** JSON의OFF/RESUME 신호만 재생하는 것과 프로세스 종료 후 Room 복원은 별개다. 선택한 제품 화면에서 저장·종료·재실행·ID/누적/단계 보존과 공백 처리까지 확인한다.
5. **부하·전시 환경 고정.** 우선1/10배로 시연하고 요청 배속과 실제 완료 시간을 구분한다.60배는 기존 null/deadline 성능 미달이 있어 완성됐다고 안내하지 않는다. 최종 설치본에서 사용자 직접 조작·실제 음성·화면 제한·중지 정리를 확인해야 한다. 현재 사용자가 APK 작업을 중단했으므로 이 기기 단계는 재개 지시 전까지 보류한다.

데모에서는 ‘제어/인증 성공’ 표시만으로 실제 SDK 실행을 성공 처리하지 않는다. 시연을 위한 명시적 가상 입력은DEMO 출처로 표시한다. SDK 물리량이나 시한을 바꿔 정상처럼 보이게 만들지 않는다.

## B. 실제 완성품 기준으로 더 필요한 것

여기서 완성품은 전체 역할이 제품 화면에서 연결된 안정적인 앱을 뜻한다. 1번이 다른 담당 알고리즘을 대신 개발한다는 뜻은 아니다.
