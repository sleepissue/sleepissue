# 디버그 수동 검증 화면 사용 가이드

`AwakeDrive 개발 검증`은 현재 운행 시간·개입 정책을 버튼으로 확인하는 개발 전용 화면이다. 최종 서비스 화면과 구별하도록 `DEBUG ONLY` 배지와 가상 입력 안내를 표시한다. 화면·조립 코드는 `app/src/debug/`에만 있으며, `release` 빌드에는 이 화면의 소스와 런처가 포함되지 않는다.

## 실행 방법

Android Studio에서 `src/android/`를 열고, **Build Variants의 app을 debug로 선택**한다. 실행 구성을 `app`으로 선택한 뒤 에뮬레이터에서 Run하면 개발 검증 화면이 열린다. 기존 JDK·SDK 설정은 [Android README](../../src/android/README.md)의 빌드 환경을 따른다.

터미널에서는 저장소 루트를 기준으로 다음과 같이 빌드·설치·실행한다. 연결된 기기가 여러 대라면 `adb -s <기기 ID>`로 대상을 선택한다.

```bash
cd src/android
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -W --user current -n com.sleepissue.awakedrive/com.sleepissue.awakedrive.debug.DebugHarnessActivity
```

앱 목록의 이름은 `AwakeDrive 개발 검증`이다. 이 화면은 SDK 입력이 없어도 가상 관측으로 동작한다. 차량 전원·음성·내비·마이크를 실제로 실행하지 않는다.

수정 APK 설치·앱 재실행으로 메모리 세션이 사라질 수 있다. 이제 마지막 성공 Room 저장본에서 실제 계산을 재개한다. 저장 실패·미지원 자료는 복원 실패로 표시한다. 같은 AVD가 이미 실행 중이면 다시 켜지 말고 `adb devices -l`로 확인한 기기에서 실행한다. Build Variants 메뉴를 찾지 못한 환경에서는 위 ADB 경로를 사용하며, IDE 메뉴 문제까지 해결된 것으로 보지는 않는다.

## 화면에서 조작할 수 있는 것

상단 **Hub 가짜 REAL/DEMO 검증**은 별도 개발 패널을 연다. [Hub 버튼별 입력·기대 출력](ROLE1_SIGNAL_HUB.md#직접-조작-순서)을 따른다. 패널의 가짜 REAL은 실제 SDK가 아니며, Hub 전용 시계·캐시를 사용해 아래 운행·Room 상태를 바꾸지 않는다. 뒤로 돌아오면 기존 수동 검증을 이어 간다.

| 조작 | 동작 |
| --- | --- |
| D / P 기어, 시동 ON / OFF | 같은 가상 시각의 기어·전원 관측을 함께 전달한다. 실제 차량을 제어하지 않는다. |
| +30초 / +1분 / +5분 / +15분 | 버튼으로만 가상 시간을 진행한다. 실제 시간을 기다려도 자동 진행하지 않는다. |
| 위험 점수·추세 적용 | 0~100의 유한한 점수와 추세형 여부를 판단 결과로 주입한다. 조향 분석기가 이 점수를 계산한 것은 아니다. |
| 휴식 인증 결과 주입 | 위치·정차 15분 자동 판정 담당이 보낼 결과를 직접 넣는다. 자동 인증 조건 검증은 생략한다. |
| 전체 테스트 상태 초기화 | 메모리 시간·운행·점수·단계·요청·기록을 교체한다. **DB 보존·자동 저장 중지**. |
| 즉시 저장 | 현재 정밀 상태·구간·개입 근거를 실제 Room에 저장한다. 자동 저장도 재개한다. |
| 저장 데이터 삭제 | 현재 화면의 메모리는 유지하고 DB 저장본을 삭제한다. 자동 저장을 중지해 곧바로 다시 생성하지 않는다. |
| 가상/실제 10초 자동 저장 | 가상 관측 또는 실제 경과 시각을 기준으로 10초 저장을 재개한다. 운행 시각은 임의 진행하지 않는다. |
| 중단된 확인 다시 요청 | 복원 때 중단한 확인을 새 ID로 다시 요청한다. 느림 뒤 재확인 등의 남은 가상 대기 시각을 지난 뒤 활성화된다. |

상단에는 연속 운전 시간, 최근 24시간 누적, 운행 ID·시작 시각·정차 시각·운전/정차 상태, 개입 단계·전환 사유, 적용된 점수·추세형을 표시한다. 입력 칸의 값은 편집 중인 값이며, **적용 버튼을 누른 결과는 상단의 ‘적용된 점수’로 확인**한다. 초기 상태와 정상 회복 뒤에는 적용 점수를 `미평가`로 표시한다.

Room의 저장·복원 상태와 실패 원인, 마지막 성공 저장의 가상/기기 시각, 자동 저장 기준·중지 여부, 정차 전 연속 시간·잠정 정차도 표시한다. 상세한 [저장·복원 버튼·종료 명령·기대 결과](ROLE1_PERSISTENCE.md)를 먼저 참고한다. 기존 단계 시험만 하려면 메모리 초기화 상태로 진행할 수 있고, 저장 시험은 자동 저장을 다시 켜거나 즉시 저장해야 한다.

2026-11-03에 점수 기반 3단계의 사유를 확인 요청 대기가 덮던 결함을 수정했다. 90점·추세형의 60초 전환은 `SCORE`이며 화면에는 `위험 점수`, 음성 요청에는 `REST_RECOMMENDED`가 표시돼야 한다. 명시적 반복 급조향 안전 우회는 `SAFETY_EVENT`와 `SAFETY_REST_RECOMMENDED`를 유지한다. 화면은 정책에서 받은 사유와 요청을 표시한다.

## 요청 결과 주입과 기록 읽기

실행 요청은 발생한 뒤 `가상 진행 중`으로 표시된다. 요청 카드의 결과 버튼은 그 요청 ID와 문맥에만 결과를 전달한다. 정책이 취소한 요청은 `취소됨`으로 남고 결과 버튼이 사라진다.

| 요청 종류 | 직접 넣을 결과 |
| --- | --- |
| 운전자·동승자 확인 | 정상 / 느림 / 무응답 |
| 휴식 후 회복 확인 | 정상 회복 / 느림 / 무응답 |
| 경유지 추가 동의 | 동의 / 거절 / 무응답 |
| 진행 방향 앞 쉼터 검색 | 후보 있음 / 후보 없음 / 실패. 후보 있음은 고정된 ‘가상 검증 쉼터’ 자료다. |
| 음성 안내·경유지 실행 | 가상 완료 / 실패 |

`가상 완료`는 실제 TTS·경유지 추가 성공을 뜻하지 않는다. 확인 결과도 실제 반응 시간을 측정하지 않고 정상·느림·무응답 판정 자체를 넣는다. 무응답 버튼을 누르지 않은 확인 요청은 가상 시간만으로 음성 장치의 무응답 판정을 만들지 않는다.

아래 이벤트 기록은 가상 시각과 순번 순서로 입력·운행 상태 변화·개입 전환·요청 발생·처리·취소를 남긴다. 같은 시각에 여러 사건이 발생하면 순번으로 순서를 확인한다. 기록 끝을 보고 있을 때는 새 이벤트를 따라가며, 이전 기록을 읽는 중에는 스크롤 위치를 유지한다.

## 재사용하는 로직과 검증 정책

수동 기어·전원 입력도 기존 `VehicleSignalHub → TripTracker → PolicyInterventionManager` 흐름을 사용한다. 위험 점수는 `DrivingAssessment`로 직접 공급한다. 화면은 기존 운행 규칙이나 개입 정책을 복제하지 않는다.

수동 시험 입력은 `Source.DEMO`를 사용하는 별도 메모리 세션이다. SDK 입력으로 표시하지 않으며 JSON 시나리오 로드·실제값 우선 중재를 검증하는 화면은 아니다.

시간 버튼은 요청한 시간을 **1초 간격의 완전 관측과 Tick**으로 나눠 전달한다. 따라서 15분을 한 번에 진행해도 중간의 30초 단계 상승·재확인·요청 대기가 시간순 기록에 남는다. 단계 정책은 `FirstEscalation.IMMEDIATE`, 요청 대기는 `RequestTimerBasis.SCENARIO`를 선택한다.

정차 계산은 기존 [운행 규칙 가이드](ROLE1_TRIP_RULES.md)의 비교 정책을 개발 화면에 명시적으로 선택했다. 제품 기본 정책을 확정하는 변경은 아니다.

- **[가정] `V03_RETROACTIVE`**: 5분 미만 정차는 연속 시간에 잠정 포함, 5분부터 정차분을 소급 제외, 15분부터 연속 시간 0.
- **[가정] `EXCLUDE`**: 정차는 최근 24시간 누적에서 제외. 연속 시간 초기화·휴식·새 운행으로 최근 24시간 구간을 지우지 않는다.

정차 15분의 연속 시간 초기화와 휴식 인증은 별개다. 휴식 인증을 주입해도 3단계는 유지하며, 그 인증에 연결된 회복 확인에서 정상 결과를 넣어야 0단계로 내려간다. 느림·무응답은 정상 회복으로 취급하지 않는다. 자세한 조건은 [개입 정책 가이드](ROLE1_INTERVENTION.md)를 참고한다.

정상 회복 뒤 생성되는 `RestRecoveryResetRequest`는 **미연결**로 남긴다. 연속 시간·평활값 초기화·예보 재계산 담당이 아직 연결되지 않았으므로 성공으로 표시하지 않는다. 화면은 `TripStateStore`의 운행 카운터만 임의로 바꾸지 않는다. 아래 절차처럼 P단 15분을 진행했다면 기존 운행 규칙이 이미 연속 시간을 0으로 만든 상태다.

## 직접 따라 할 검증 순서

### 느린 응답 두 번과 휴식 후 회복

1. **전체 테스트 상태 초기화**를 누른다. P / 시동 ON / 가상 시간 0 / 점수 미평가를 확인한다.
2. **D 기어**를 누르고 위험 점수 **64**, **추세형**을 선택한 뒤 적용한다. 1단계와 관련 요청을 확인한다.
3. **+30초**를 누른다. 2단계와 운전자 확인 요청을 확인한다.
4. 활성 운전자 확인 요청에 **느림**을 넣는다.
5. **+30초**를 누르고 새 확인 요청에 다시 **느림**을 넣는다. 3단계가 되는지 확인한다. 두 번째 확인 결과는 다음 30초를 기다리지 않고 반영된다.
6. **P 기어 → +15분**을 누른다. 연속 시간은 0이며 최근 24시간 누적은 남아 있다. 3단계는 유지한다.
7. **휴식 인증 결과 주입**을 누른다. 회복 확인 요청이 발생하고 3단계는 유지한다.
8. 회복 확인 요청에 **정상 회복**을 넣는다. 0단계와 미평가 점수, 미연결 상태 초기화 요청을 확인한다.

쉼터 검색 요청에는 필요할 때 `후보 있음`을 넣어 후속 음성·경유지 동의·경유지 실행 요청도 확인할 수 있다. 각 요청은 가상 결과 버튼으로 완료시킨다.

### 높은 점수의 단계별 상승

아래 순서가 인계 문서 4절 결함의 수동 회귀 시험이다. 단계뿐 아니라 사유와 안내 요청까지 함께 확인한다.

| 순서 | 누를 버튼·입력 | 기대 결과 |
| --- | --- | --- |
| 1 | 전체 테스트 상태 초기화 → D 기어 | 가상 0초, 운전 중, 단계 0·미평가. |
| 2 | 점수 **90**, **추세형** 체크 → 위험 점수·추세 적용 | 0초 **1단계 · 위험 점수**. 이벤트 `0 → 1 / 전환 이유: SCORE`, 쉼터 검색 요청. |
| 3 | **+30초** | 30초 **2단계 · 위험 점수**, `SCORE`. 운전자 확인 요청 발생. **정상·느림·무응답을 누르지 않고 대기시킨다.** |
| 4 | 다시 **+30초** | 60초 **3단계 · 위험 점수**, 이벤트 `2 → 3 / 전환 이유: SCORE`. **음성 안내 요청: REST_RECOMMENDED**와 새 쉼터 검색. 이전 운전자 확인은 취소됨. |
| 5 | P 기어 → **+15분** | 가상 16분, 연속 0·최근 24시간 1분. **3단계·SCORE 유지**, 재안내도 일반 `REST_RECOMMENDED`. |
| 6 | **휴식 인증 결과 주입** | **3단계 유지**, 휴식 후 회복 확인 요청. 카드가 아래에 있으면 요청 목록을 스크롤한다. |
| 7 | 그 요청의 **정상 회복** | **0단계 · 휴식·회복 완료**, `REST_COMPLETED`, 적용 점수 미평가·최근 누적 1분 유지. 상태 초기화 요청은 **미연결**. |

4번에서 `SAFETY_EVENT` 또는 `SAFETY_REST_RECOMMENDED`가 나오면 실패다. 수정 화면의 [60초 증거](../devlog/evidence/2026-11-03-score-reason/03_점수90_60초_SCORE_일반안내.png)와 비교할 수 있다. 초기화 후 같은 입력에 **+1분**을 한 번 눌러도 기록에는 30초의 2단계와 60초의 3단계가 각각 남아야 한다.

명시적 안전 우회 주입 버튼은 현재 화면에 없다. 해당 경로의 즉시 3단계·안전 안내는 정책·관리자 자동 시험에서 검증하며, 운전자 확인의 무응답 버튼을 안전 우회 시험으로 대신하지 않는다. 확인 결과의 무응답·느림 두 번·휴식 의도는 `CHECK_RESULT`와 일반 휴식 안내 경로다.

## 세션 수명과 범위

화면 회전 등 Activity 재생성 시 `ViewModel`이 검증 세션을 보존한다. 프로세스 종료 후에는 Room의 정밀 운행·개입 상태에서 저장 가상 시각으로 재개한다. 닫혀 있던 실제 시간은 운전에 합산하지 않고 앱 종료를 OFF로 처리하지 않는다. 메모리 이벤트·요청 카드는 그대로 복원하지 않으며, 중단된 확인은 사용자가 다시 요청한다.

메모리 초기화는 기존 관리자의 시계를 뒤로 돌리지 않고 Clock·Hub·Tracker·Store·Manager·요청 수집기·ID를 새 세션으로 만든다. DB는 남기고 자동 저장을 중지한다. DB 삭제는 별도 버튼이며, 실제 차량·부팅·백그라운드 복원은 아직 별도 범위다.

이 화면의 범위는 Kotlin 운행·개입 로직, 가상 입출력, 수동 세션 Room 저장·프로세스 재실행 복원이다. Playground SDK 수신, 실제 TTS/STT·내비 동작, 위치 기반 인증·보상, 실제 재부팅 시간축·FGS·부팅 자동 실행, 최종 Compose 서비스 화면은 별도 구현·검증 대상이다. TRP_003 전체 완료를 뜻하지 않는다.
