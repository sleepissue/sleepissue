# 운행 상태 Room 저장·복원 가이드

2026-11-07: 실제 Playground SDK 운행도 별도 `awakedrive_sdk_trip.db`에 연결했다. [실제 SDK 운행·Room 가이드](ROLE1_REAL_TRIP.md)의 WALL_EPOCH/UNKNOWN 복원 계약을 따른다. 아래의 수동 DB·개입 저장 형식과 기존 시험 기록은 그대로 보존한다. 현재 감시·부팅 재개는 [서비스 가이드](ROLE1_MONITOR_SERVICE.md)에 구현돼 있으며 실제 차량 STR/ignition 검증과 구분한다. 요구별 최신 판정은 [현황표](ROLE1_COMPLETION_STATUS.md)를 따른다.

이 문서의 기본 예시는 **디버그 수동 세션의 Room 저장과 프로세스 재실행 복원**이다. 메모리 화면 값뿐 아니라 `TripTracker`의 정밀 상태와 `PolicyInterventionManager`의 판단 상태를 함께 복원한다. 수동 예시에는 실제 차량의 재부팅 시간 변환·SDK 수신·감시 서비스·부팅 자동 실행이 없다. 실제 SDK 수신·운행·감시 서비스·부팅 재개는 별도 REAL 경로로 구현돼 있다. **TRP_003 전체 완료가 아니다.**

## 저장소와 호환성

- `app/data/TripDatabase.kt`: Room DB·상태 행·운전 구간·트랜잭션 DAO. 상태와 구간은 전부 성공할 때만 함께 교체되며 실패하면 이전 저장본을 유지한다.
- `app/data/RoomTripRepository.kt`: 기존 `TripRepository` 계약의 실제 구현. 빈 DB·저장/조회 실패·손상·미지원 버전을 구별한다.
- `app/signal/TripSaveCoordinator.kt`: 저장 주기·명시적 저장·삭제·복원 표시. 운전 시간을 계산하거나 시동을 추론하지 않는다.
- `app/signal/InterventionCheckpoint.kt`, `TripSessionCodec.kt`: 개입 판단·인증·중단된 확인의 논리 시각 보존. 실행 요청 ID나 경유지 실행 예약을 재생하지 않는다.
- `engine/session/TripSnapshotValidator.kt`: Android 없이 공개 상태·정밀 근거·구간 합계의 일관성 검증.

의존성은 app에 **Room runtime/compiler 2.8.5 + KSP2 2.3.13**만 추가했다. AGP 9.4.0·Kotlin 2.4.21·Gradle 9.6.0·현재 설정은 minSdk 28·compileSdk 37·targetSdk 34다. 당시 Room 도입 이후 target만 34로 변경했고 이번에는 도구/의존성 버전을 바꾸지 않았다. [Room 공식 의존성·호환 조건](https://developer.android.com/jetpack/androidx/releases/room), [AGP 내장 Kotlin의 KSP 안내](https://developer.android.com/build/migrate-to-built-in-kotlin), [KSP 공식 릴리스](https://github.com/google/ksp/releases)를 확인하고 실제 빌드·기기 시험을 수행했다. 전체 도구 조합을 공식 호환 표가 보증한다는 뜻은 아니다.

디버그 DB는 앱 내부의 `awakedrive_debug_trip.db`다. SDK/제품 세션과 섞지 않는 별도 DB이며 실제 저장소 구현은 main 소스에 있어 후속 제품 조립에서도 사용할 수 있다. 스키마는 `app/schemas/...TripDatabase/1.json`으로 내보낸다. 파괴적 마이그레이션은 사용하지 않는다. 후속 스키마 변경에는 버전 증가·명시적 마이그레이션이 필요하다. DB는 [Android 백업 규칙](https://developer.android.com/identity/data/autobackup)에서 클라우드·기기 이전 제외 대상으로 지정했다.

## 저장하는 자료와 검사

| 자료 | 처리 |
| --- | --- |
| SRS 10종 | 운행 ID·연속 시간·기준선 참조·단계·위도·경도·기어·운행 시작·정차 시작·운전 상태. 미관측 위치·기준선은 null 그대로 유지 |
| 운전 구간 | 정규화한 `DriveSegment`의 시작·끝 ms·순서·개수. 구간 누락·순서 오류를 검사하며 최근 24시간 합계는 구간에서 다시 계산 |
| 정밀 운행 근거 | 연속 ms·정차 전 연속 ms·잠정 정차 초·마지막 기어/전원 관측과 논리 시각·OFF 시작·새 운행 대기·휴식 초기화 통지 여부 |
| 정책·시간축 | V03_RETROACTIVE/EXCLUDE 선택, Source.DEMO, MANUAL_SCENARIO, 저장 가상 시각·기기 날짜 시각·부팅 내 실제 경과 시각 |
| 개입 판단 | 단계·사유·상승/하강 기준 시각·시간/예보 유지·정상 확인·느림 횟수·민감 모드·마지막 판단·예보·인증 세션·회복 완료 근거 |
| 재개할 확인 | 운전자/동승자/회복 확인의 문맥과 재요청 가능 가상 시각. 과거 요청 ID·오디오·문장은 저장하지 않음 |

공개 카운터만 있는 예전 `TripSnapshot` 호출은 표현할 수 있지만 실제 Room 저장·정상 복원에는 충분하지 않아 `INVALID_DATA`로 거부한다. 운행 ID·기준선 참조는 기존 코드의 String을 보존했다. Excel의 Long ID와 변환하는 외부 계약은 별도 합의 대상이다.

MSG-15의 진행 중 `endMs=null`은 내부에서 **관측 시각까지 확정한 구간 + 마지막 관측/정밀 상태**로 표현한다. D단에서 저장하면 다음 가상 관측부터 새 구간을 이어 더한다. 프로세스를 닫았다는 이유로 OFF나 정차 구간을 만들지 않는다.

저장본의 공개·정밀 단계, 연속 ms/초, 정차 시작·정차 전 기준, 구간 개수·정렬·24시간 합계, 마지막 관측 시각, 개입 평가 시각과 인증 근거를 대조한다. 결과 코드는 `EMPTY`, `INVALID_DATA`, `STALE_INPUT`, `UNSUPPORTED_VERSION`, `UNSUPPORTED_TIME_BASIS`, `UNAVAILABLE`로 구별한다. 실패한 저장은 마지막 성공 시각·성공 횟수를 갱신하지 않는다. 복원 실패 시 기존 DB를 보존하고 새 메모리 세션의 자동 저장을 중지한다.

## 두 저장 주기와 시간 재개

| 선택 | 10초의 기준 | 앱을 닫았다 열 때 |
| --- | --- | --- |
| 가상 10초 자동 저장 | 가상 시간 버튼이 보내는 관측·Tick의 10초. 실제로 기다리기만 하면 운전 시각·주기가 진행하지 않음 | 저장 가상 시각부터 그대로 재개 |
| 실제 10초 자동 저장 | `elapsedRealtimeMs()` 기준, 화면 소유 작업이 약 1초마다 확인 | 저장 주기 기준은 현재 실제 경과 시각으로 다시 잡음. 닫힌 시간을 운전 시간으로 더하지 않음 |
| 즉시 저장 | 주기와 무관하게 현재 일관된 상태를 저장 | 성공한 시점의 상태로 재개 |

모든 저장에는 별도의 **가상 시각·기기 날짜 시각·실제 경과 시각**을 남긴다. 수동 운행 시각과 실제 저장 주기의 시계를 서로 빼지 않는다. 가상 시간을 한 번에 15분 진행해도 기존 1초 관측 중 10초 경계마다 저장한다.

큰 가상 시간 진행은 중간 판단·Room 쓰기·화면 갱신을 모두 거치므로 실제 처리가 잠시 걸릴 수 있다. 버튼을 연속으로 반복하지 말고 상단 가상 시각이 목표에 도달하고 이벤트에 **가상 시간 진행 완료**가 나타난 뒤 다음 입력을 한다.

기존 수동 경로는 실제 차량 시간축(`ELAPSED_REALTIME`) 복원을 지원하지 않는다. 새 SDK 전용 경로는 별도 `WALL_EPOCH` 이력을 UNKNOWN 활성 상태로 복원한다. 저장된 REAL 입력은 신선한 차량 관측으로 재사용하지 않고 `STALE_INPUT`으로 구별한다. 수동 세션은 ‘저장한 수동 입력 재개’로 표시한다. 수동 시각은 실제 날짜가 오래 지났어도 자동으로 진행하지 않는 사용자 설정값이다.

REAL의 BOOT_COMPLETED·FGS·새 시계 앵커 복원은 구현돼 있다. 재부팅 전후 elapsed를 직접 변환해 합산하지 않는다. 꺼진 시간·실제 OFF의 증명과 차량 STR은 현재 AVD에서 별도 제약이다. 수동 저장본을 사용자가 다시 여는 경로와 실제 부팅 자동 복원을 혼동하지 않는다. 화면이 살아 있는 범위의 저장 주기를 검증했으며 백그라운드·절전 중 10초 저장 보장까지 완료한 것은 아니다.

이후 추가한 [Hub 주기·품질 시험](ROLE1_SIGNAL_HUB.md)은 별도 패널·가짜 시계를 사용한다. Room 수동 운행의 관측 경로와 저장 시계는 유지하며, 가짜 REAL 입력이나 Hub 시험 시간을 저장된 운행에 합산하지 않는다. Hub 시험 상태 자체는 Room에 저장하지 않는다.

## 화면 버튼의 의미

| 버튼 | 메모리 | DB·자동 저장 |
| --- | --- | --- |
| 전체 테스트 상태 초기화 | 운행·시간·단계·판단·요청·기록을 새 세션으로 초기화 | **DB 보존**, 자동 저장 중지. 재실행하면 이전 저장본을 읽을 수 있음 |
| 저장 데이터 삭제 | 현재 운행 상태 유지 | 상태·구간·개입 저장본 삭제, 자동 저장 중지. 즉시 다시 생성하지 않음 |
| 즉시 저장 | 현재 상태 유지 | 현재 메모리로 DB 갱신, 자동 저장 재개 |
| 가상/실제 10초 자동 저장 | 운행 시간을 임의 진행하지 않음 | 선택한 기준으로 자동 저장 재개. 기존 저장본은 다음 저장 때 현재 메모리로 갱신 |
| 중단된 확인 다시 요청 | 복원한 판단·인증 조건 유지 | 기한이 지난 중단 확인만 새 요청 ID로 시작. DB에 있던 요청을 자동 재실행하는 동작 아님 |

상단에서 Room 저장 상태, 복원 성공/실패·사유, 마지막 성공 저장의 가상/기기 시각, 저장 주기와 켜짐/중지 상태를 확인한다. 성공 횟수는 현재 프로세스의 저장 횟수다. 정차 전 연속 시간·잠정 정차도 표시한다.

앱 재실행 때는 `TripTracker`·`TripStateStore`·개입 정책의 단계가 같은 저장본으로 구성된다. 과거 이벤트 목록·요청 카드는 메모리 자료이므로 그대로 복원하지 않는다. 복원 자체는 새 음성·쉼터 검색·경유지를 발행하지 않는다. 이후 사용자가 시간을 진행하거나 입력을 바꾸면 현재 판단에 따른 새 요청은 발생할 수 있다.

## 직접 확인 1: D단 2분 → P단 3분 → 종료·재실행

새 독립 시험을 위해 DB를 비울 때만 1번의 삭제를 사용한다. 기존 저장본을 유지하고 싶다면 삭제하지 않는다. APK 재설치·프로세스 종료는 메모리 세션을 잃을 수 있으며, `pm clear`·앱 제거·AVD Wipe는 이 복원 시험에서 사용하지 않는다.

`connectedDebugAndroidTest`는 테스트 러너가 대상 APK를 설치·제거하므로 수동 저장본도 지워질 수 있다. 보존할 수동 세션이 있는 기기에서는 기기 시험을 먼저 실행한 뒤 수동 시험을 시작한다. 일반 복원 확인에는 아래 `am force-stop`/`am start`만 사용한다.

1. **저장 데이터 삭제 → 전체 테스트 상태 초기화 → 가상 10초 자동 저장**을 누른다.
2. **D 기어 → +1분 두 번**. 가상 2분, 연속 2분·최근 누적 2분을 확인한다.
3. **P 기어 → +1분 세 번**. 가상 5분, 정차 시작 2분·정차 전 연속 2분·잠정 정차 3분을 확인한다. 이때 연속 시간은 v0.3 규칙에 따라 **잠정 5분**, 최근 누적은 **2분**이다.
4. **즉시 저장**을 누르고 **Room 저장 성공**, **마지막 저장 가상 +00:05:00**을 확인한다. 운행 ID도 기록한다.
5. 아래 명령으로 강제 종료하고 다시 연다. 닫아 둔 실제 시간은 더하지 않아야 한다.

```bash
adb -s emulator-5554 shell am force-stop --user current com.sleepissue.awakedrive
adb -s emulator-5554 shell am start -W --user current -n com.sleepissue.awakedrive/com.sleepissue.awakedrive.debug.DebugHarnessActivity
```

6. **복원 성공**, 같은 가상 5분·운행 ID·P/ON·정차 시작 2분·정차 전 연속 2분·최근 누적 2분을 확인한다. 연속 시간은 여전히 잠정 5분이다.
7. **+1분 두 번**. 가상 7분·정차 총 5분이므로 연속 시간이 정차 전 **2분으로 소급 보정**된다. 최근 누적은 2분이다.
8. **+5분 두 번**. 가상 17분·정차 총 15분이므로 연속 **0분**, 최근 누적 **2분**이다. 실제 시동 OFF를 만들어 낸 결과가 아니다.

기기 ID가 다르면 `adb devices -l`의 실제 ID를 사용한다. 에뮬레이터는 이미 켜진 인스턴스 하나를 사용한다.

## 직접 확인 2: 개입 단계·인증·회복 복원

1. **전체 테스트 상태 초기화 → D → 90점·추세형 적용 → +1분 → 즉시 저장**. 0/30/60초의 단계는 1/2/3, 3단계 사유는 `SCORE`, 음성 요청은 일반 `REST_RECOMMENDED`다.
2. 같은 종료·재실행 명령을 실행한다. **3단계·SCORE**를 복원하고 요청 목록은 비어 있어야 한다. 과거 음성·경유지가 자동 실행되면 실패다.
3. **P → +15분 → 휴식 인증 결과 주입 → 즉시 저장**. 인증만으로는 3단계를 유지한다.
4. 다시 종료·재실행한다. **3단계 유지**, 요청 자동 재실행 없음, **중단된 확인 다시 요청**이 가능해야 한다.
5. **중단된 확인 다시 요청 → 새 회복 확인의 정상 회복**. **0단계·REST_COMPLETED·점수 미평가**가 된다. 최근 누적은 1분 유지, 실제 초기화 담당 요청은 기존과 같이 `NOT_CONNECTED`다.
6. **즉시 저장 → 종료·재실행** 후 0단계가 유지되고 회복 확인을 다시 요구하지 않는지 확인한다.

이미 저장된 인증이 있으면 인증 버튼을 반복하는 대신 **중단된 확인 다시 요청**을 사용한다. 2단계의 느림 1회 뒤 재확인 예약도 남은 가상 시각을 보존한다. 예를 들어 30초에 느림을 저장했다면 가상 60초부터 재요청 버튼이 활성화된다. 느림·무응답 회복은 3단계를 해제하지 않는다.

## 직접 확인 3: 삭제와 메모리 초기화 구별

- 저장 후 **전체 테스트 상태 초기화**를 눌러 메모리가 0이 돼도 DB는 남는다. 자동 저장을 다시 켜지 않고 종료·재실행하면 이전 저장본이 복원된다.
- **저장 데이터 삭제** 뒤에도 화면의 운행 값은 유지된다. 자동 저장이 중지되므로 그대로 종료·재실행하면 **빈 DB·가상 0초**가 된다.
- 저장 실패·잘못된 저장본은 화면에 실패와 원인이 표시되며, 마지막 성공 저장을 현재 값으로 바꾸거나 실패 DB를 새 세션으로 자동 덮지 않는다. 오류 주입은 자동 시험에서 검증한다.

실행한 시험·기기 증거와 남은 범위는 [개발 기록의 Room 절](../devlog/2026-11-03.md#room-저장복원-구현)을 참고한다.
