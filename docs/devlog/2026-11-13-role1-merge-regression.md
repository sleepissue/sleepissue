## 재현한 병합 후 문제와 수정

최초 전체 실행에서 엔진359개는 통과했고 앱521개 중12개가 실패했다.

| 문제 | 수정 |
|---|---|
| 1번 데모 계약 시험9개가 옛 30분/18,000개·팀 tMs 형식을 기대 | 최신 표준 t 형식과 팀 tMs 형식의 시각/epoch를 구분한다. 원본 길이·샘플 수·preset을 그대로 대조한다. |
| 원본 배속 시험의 `100/60` 정수 나눗셈으로 수동 시계가 원본을 따라가지 못함 | 시험의 실제 시계를 구간 길이/배속 적분 뒤 ms 올림으로 계산한다. 생산 DemoClock·Hub 시간축은 유지한다. |
| 최신 정상/대화 원본의 의도와 이전 기대값 불일치 | 10시 정상은 점수0·단계0, 급조향이 들어간 대화 원본은 확인 단계 도달을 검증한다. 출발 피로 첫 확인 예약은 45분 원본 안에 있어야 한다. |
| 1번 요청↔음성 어댑터의 시작 표시 누락으로 동승자 응답 거부 | 실제 안내 시작 시 `promptStarted`를 갱신한다. 버튼 대체 중 응답도 허용하며 중복 응답·취소 뒤 늦은 인식 차단을 유지한다. |
| 동승자 응답 후 데모 질문 잠금이 풀리지 않음 | 수락된 완료에 SUCCEEDED lifecycle을 전달한다. 실제 DemoVoiceSpeedGate를 사용해 60→1→60을 검증한다. |
| 경유지/회복 등 직접 질문에서 마이크 없음에도 STT 시작 | 안내 완료 후 권한을 확인하고 버튼 대체로 넘긴다. 음성 알고리즘·항상 운전자에게 묻는 기존 정책은 유지한다. |
| 마이크 없는 즉시 버튼 대체에서 실행 시작 이벤트 누락으로 시험 대기 | 버튼 요청 활성은 execution STARTED로 알리되 실제 음성 lifecycle STARTED는 발행하지 않는다. 배속 잠금을 만들지 않는다. |

버튼 결과는 lock 안에서 요청을 먼저 소비한다. 결과 발행 뒤 다시 clear하여 새 요청을 지우는 중복 정리도 제거했다.
