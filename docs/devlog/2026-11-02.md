## Playground 환경과 출처

개발 대상은 물리 차량이 아닌 Pleos Playground의 가상 차량(Pleos Connect Emulator)이다. `Source.REAL`은 SDK·Virtual Console에서 공급되는 입력, `Source.DEMO`는 앱 내부 JSON 재생 입력이다. 이 정의를 AGENTS·CLAUDE·공통 모델 주석·연결 가이드에 함께 명시했다.

Virtual Console은 에뮬레이터 차량 상태를 조작하는 도구이고 앱은 차량 SDK/AAOS의 변경 통지를 받는다. Virtual Console 웹 API를 별도 앱 입력 프로토콜로 만들지 않는다. [공식 설정 가이드](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/use-vehicle-emulator), [공식 Console 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide).

이번 재개 시점 `adb devices -l`은 연결 기기 0대를 반환했다. 에뮬레이터·포트·서비스를 시작하거나 변경하지 않았다. 따라서 SDK 콜백 수신·기어 변경 반영을 실제 확인한 것으로 표시하지 않는다.

## 정책 적용 기준

외부 실행 계획 v0.3 9절과 SRS 수정 방안 v0.2 C-1~C-3에는 정차 5분 소급 제외·15분 초기화·최근 24시간 누적·첫 D단 시작이 구체적으로 있다. 저장소 현재기능 기획서 7-2의 정차·누적 표현과 차이가 남아 있다.

기획서를 자동 변경하지 않고 정책을 호출자가 명시적으로 선택하도록 구현한다. v0.3은 선택 가능한 계산 정책이며 앱의 자동 기본값으로 활성화하지 않는다. 짧은 정차의 최근 24시간 누적 포함 여부도 별도 선택이다. 예시의 제외 선택은 [가정]이며 팀 확정으로 간주하지 않는다.

## 구현·검증

### 구현 내용

- `TripRules`: 명시적 정책 주입, 첫 D단 시작, 밀리초 정밀 누적, P/OFF 정차 합산, v0.3의 5분 소급 보정·15분 초기화, OFF 2시간 초과 후 첫 D단에서 새 운행 생성.
- `RollingDriveWindow`: 시간 창 절단, 중복·겹침·인접 구간 합집합, 원래 시간축 보존. 자정·휴식·새 운행으로 최근 구간을 초기화하지 않는다.
- `TripRuleState`: 공개 초 단위 상태와 정밀 ms·구간·정차·OFF 근거의 일관성을 검증한다. 카운터만 있는 불완전한 상태를 복원 성공으로 받아들이지 않는다.
- `TripTracker`: 같은 세션 출처의 유효 기어·전원을 받아 계산하고 Store에 투영한다. 다른 출처는 무시하고 같은 출처의 미관측은 UNKNOWN으로 전달한다. 입력 중단을 명시하는 통로를 제공한다.
- `TripStateStore`: 단일 잠금의 transaction으로 콜백을 한 번만 실행해 동시 첫 D단에서도 ID가 중복 생성되지 않게 했다. 외부 소유 단계·기준선·위치를 보존한다.
- `EngineConfig`: 정차 300,000ms/900,000ms, 새 운행 OFF 경계 7,200,000ms, 최근 창 86,400,000ms를 모았다. 잠정 짧은 정차를 보관하도록 누적 창은 짧은 정차 경계 이상이어야 한다.

[운행 규칙 사용 예시·계약](../setup/ROLE1_TRIP_RULES.md)에 정책의 [가정], Source 의미, 완전한 관측 조립, 입력 중단 시각, 메모리 정밀 상태와 후속 영속 복원의 차이를 정리했다.

강화한 초기 정밀 상태 계약을 반영하는 과정에서 앱 시험 1개가 불완전한 초기 데이터로 실패했다. 마지막 관측·첫 D단·구간·정밀 시간을 모두 제공하는 정상 주입 사례로 고치고, 600ms를 추가 관측해 2,100ms까지 이어 계산되는 것도 검증했다. 첫 D단 이전 P단 관측이 잠정 운전 시간을 만들던 경계도 수정하고 회귀 시험을 추가했다.

주요 시험은 299.999/300/899.999/900초 정차, P→OFF 합산과 OFF 타이머 분리, 정확히 2시간/초과, 같은 시각 중복·역행, 서브초 누적, 입력 중단, 출처·권한·STALE, 새 운행의 단계/위치/누적 보존, 23~25h·33~35h 운전 후 48h 부분 절단·49h1m 만료, 동시 ID 생성 1회를 다룬다.

### 남은 범위

- 다음 구현은 개입 단계 정책·실행 요청 관리다. 이어 JSON 재생, 신호 품질·주기 발행, Playground SDK 입력 조립·수신, 저장·복원·서비스를 연결한다.
- 독립 SDK 콜백을 같은 시각의 완전한 관측으로 조립하는 계층은 아직 없다. 단발 OFF 이벤트를 다음 모든 프레임에 자동 유지하지 않으며, null을 이전 값 유지 명령으로 취급하지 않는다.
- 상태는 다음 관측 시각까지 직전 상태가 유효한 구간 모델이다. 소유자는 실제 유효 구간이 끝난 논리 시각에 입력 중단을 알려야 한다. 최신성 타이머와 소급 장애 보정은 후속 범위다.
- `RestResetReached`는 연속 시간 초기화 통지이며 인증·보상·단계 해제 완료가 아니다. 새 운행 기준선 재설정도 요청 이벤트까지만 제공한다.
- 제품 정책 정합성, 짧은 정차의 누적 포함, 첫 D단 이전 R/N 범위 등 [가정]을 공동 결정해야 한다. 원문 기획서·Excel은 자동 개정하지 않았다.
- 에뮬레이터 기기 시험·SDK 수신·Room·서비스·UI·JSON 재생은 미수행이다.
- 변경은 개인 브랜치의 로컬 미커밋 상태로 남겼다. 이번 단계에서 push·공용 develop 생성·PR·merge는 수행하지 않았다.

## SRS v0.2 개입 동작 보완

### 기준과 변경 전 상태

같은 `develop-jdw`·HEAD `309636676659f91ceed6e1586abad97f65225a4e`에서 기존 미커밋 파일을 보존해 메인 에이전트가 직접 이어 작업했다. 기존 보조 작업을 재사용하지 않았다. 수정 전 소스·문서 등 122개 파일의 해시를 기록해 관련 파일 외 변경 여부를 비교했다.

기준 원본 `/home/a/Downloads/AwakeDrive_SRS_TC_v0.2.xlsx`의 요구사항·TC INT_004(36행), INT_006(38행), INT_008(40행), INT_015(191행)를 직접 다시 읽었다. 원본 SHA-256은 `2ea8c6d0baf3040f146fbbab0d87883f12108354411ffaad1f8e6fb1e95e69da`이며 수정하지 않았다. 저장소 현재기능 기획서 5장 단계·7장 휴식 및 기존 개입 코드·시험도 대조했다.

기존 코드에는 단계 계산·ID 기반 요청 관리가 있었지만 1단계의 시간·예보 유지 조건도 정상 회복까지 해제되지 않았다. 최초 상승 대기 여부를 문서 미명시로 적었고, 미확정 INT_015와 다른 ‘2단계 진입 즉시 안내’ 선택 경로가 있었다. 수정 전 저장된 XML에는 engine 55개·app 62개, 합계 117개 통과 기록이 있었다.

### 변경 내용과 회귀 검증

- **INT_006:** 한 평가에만 사용하는 `restCertified` 입력을 추가했다. 과거 맥락으로 유지된 1단계는 인증 시 유지 조건을 풀고 현재 조건을 재평가한다. 점수 0이면 10분 대기 없이 해제하지만, 점수 40/민감 30 경계·새 시간/예보·취약 시간대·확인 조건은 지우지 않는다. 단계가 같아도 표시 사유를 현재 조건으로 갱신한다. 점수 단독 1단계에는 기존 INT_005의 10분 하강 규칙을 유지한다.
- Manager는 인증 전 `trip`·`forecast` 캐시를 만료시킨다. 실제 TripStateStore나 예보 엔진 초기화 완료를 뜻하지 않으며, 휴식 후 현재 값은 소유 모듈이 다시 공급한다. 인증 직후 점수·분석 가용성은 보존한다.
- **INT_008:** 인증만으로 3단계를 해제하지 않는 동작을 유지했다. 인증 없는 정상 회복 결과, 느림·무응답·장치 사용 불가, 졸림 의도는 해제하지 않는다. 정상 회복 뒤 reset 요청 발행까지이며 실제 RES_011 전체 연결은 남아 있다.
- **INT_004:** 생성자 기본값과 연결 가이드를 IMMEDIATE로 맞췄다. 기존 AFTER_INTERVAL 비교 시험은 제품 기준과 구분했다. R=90+추세형의 전환 시각 0/30/60초, 직전 29.999/59.999초와 이전 정상 평가가 있던 경우, 느림 2회·무응답·REST·안전 우회의 즉시 전환을 검증했다.
- **INT_015:** 미확정 Should로 유지하고 `suggestRestAtCheck` 인자 및 활성화 분기를 제거했다. 정상·느림 결과와 취소된 1단계 검색 응답이 2단계 쉼터 안내로 이어지지 않는지 검증했다. 필수 구현 완료 항목으로 세지 않는다.
- 추가 회귀 시험은 engine 6개·app 7개다. 1단계 30분 재안내 경계, 현재 점수 재평가, 새 예보 재진입, 출처·중복 인증, 3단계 회복 게이트도 포함했다.

실제 앱 조립 지점은 아직 없다. [개입 정책 연결 가이드](../setup/ROLE1_INTERVENTION.md)에 IMMEDIATE 생성 예시, 입력 캐시 만료·새 상태 공급, 요청과 실행 완료의 차이, 남은 연결을 명시했다.
