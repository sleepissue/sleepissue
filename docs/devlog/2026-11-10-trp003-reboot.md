## 격리와 제품 경로

OS가 받는 컴포넌트는 기존 **MonitorBootReceiver 자체**다. 별도 가짜 BOOT Receiver나 runner의 서비스 직접 시작은 없다.

`OS BOOT_COMPLETED → MonitorBootReceiver.onReceive → 기존 MonitorPreference.reconcileUserStop/requested 판정 → startForegroundService(ACTION_BOOT) → DebugBootMonitorService → 제품 RealTripMonitorService.onStartCommand → 기존 Runtime/Room 복원 → 실제 PlaygroundMonitorInput`

main 변경은 선택적 MonitorBootEnvironment 경계다. 실제 release Application이 이를 구현하지 않으면 기존 사용자 Context·RealTripMonitorService 대상으로 그대로 실행한다. debug Application만 명시적 arm에서 기존 prefix 저장소와 격리 서비스 대상을 선택한다. 중지 보호·BOOT 예외/거부 처리·운행/저장 정책은 바꾸지 않았다.

격리 구현·준비 화면·계측 서비스는 debug, 준비/정리 runner는 androidTest다. DebugBootMonitorService는 기존 DebugIsolatedMonitorService를 상속하며 사용자 DB·prefs·cache를 열지 않는다. 기존 prefix `role1-final-20261109-`와 새 cache `trp003-runId`를 썼다. 실제 SDK/Clock·서비스 실행/타이머는 제품 경로다. 새 관측을 만들기 직전과 첫 유효 기어 수신 직전에만 상태를 기록한다. debug의 RUNTIME_STARTED 로그와 파일 이벤트는 같은 사실을 남긴다.

release manifest는 기본 Application·제품 Receiver/서비스만 포함하고, release 자체 Kotlin663개 클래스에서 DebugBootApplication/서비스/arm 설정 참조0을 확인했다. 공통 환경 **인터페이스**는 release에 존재하지만 debug 구현·설정·UI는 없다. [release 검사](evidence/2026-11-10-trp003-reboot/release-isolation.json). 사용자 DB를 대상으로 한 양성 재개를 이번에 실행한 것은 아니며, 격리 대상으로 동일 제품 Receiver·서비스 구현을 검증한 범위다.

### 저장 이력과 현재 UNKNOWN

- `restoredSnapshot`의10종과 전체 자료는 저장본 그대로다.
- 입력 생성 전 현재 driveState=UNKNOWN, precise.lastObservation.gear/power=null, stopStartedAtMs/offStartedAtMs=null이다. `TripState.lastGear=P`는 마지막으로 저장된 역사 필드이며 현재 관측이 아니다.

```bash
  -e role1Boot prepare -e role1BootRunId "$trial_id" \
  com.sleepissue.awakedrive.test/androidx.test.runner.AndroidJUnitRunner

# 보이는 화면에서 [다음 부팅 재개 허용]을 누른다. 기대: requested=true, 서비스0.
adb shell am start --user 10 \
  -n com.sleepissue.awakedrive/.debug.DebugBootArmActivity \
  --es role1BootRunId "$trial_id"

adb shell cat /proc/sys/kernel/random/boot_id
adb reboot
adb wait-for-device
```

재접속만으로 부팅 완료를 판정하지 않는다. **boot_id가 달라지고 sys.boot_completed=1·현재사용자10·새 BOOT 이벤트가 확인될 때까지** 기다린다. 그동안 앱 UI/runner·서비스 시작 명령을 실행하지 않는다.

```bash
adb shell getprop sys.boot_completed
adb shell am get-current-user
adb shell cat /proc/sys/kernel/random/boot_id
adb logcat -d -v threadtime -s Role1BootAudit:I

  com.sleepissue.awakedrive/.debug.DebugBootMonitorService
adb exec-out run-as com.sleepissue.awakedrive --user 10 cat \
  "cache/role1-final-20261109-diagnostics/trp003-$trial_id/events.jsonl"
```

기대값은 새 bootCount의 BOOT_RECEIVED/START_REQUEST/SERVICE_CREATE/INPUT_CREATED/RUNTIME_STARTED 각1, starts1/timers1, RESTORED_BEFORE_INPUT의원본10종 일치/활성UNKNOWN이다. 첫 새 유효 프레임 전까지 현재 관측 기어·전원null을 대조한다.

**알림 패널 → 감시 중지** 후 requested=false·SERVICE_DESTROY의 running=false/timers0/owner=null·서비스 없음을 확인하고 다시 `adb reboot`한다. 새 boot_id·BOOT_COUNT에서 BOOT_RECEIVED/REQUEST_SKIPPED 각1·새 서비스/입력/타이머0과 중지 DB 동일이 기대값이다. 첫 단계의 누적 이벤트를 둘째 부팅의 새 시작으로 세지 않는다.

시험 준비 화면이 남아 있으면 같은 runId로 가져와 BACK으로 닫은 뒤 정리한다.

```bash
adb shell am start --user 10 --activity-reorder-to-front \
  -n com.sleepissue.awakedrive/.debug.DebugBootArmActivity \
  --es role1BootRunId "$trial_id"
adb shell input keyevent KEYCODE_BACK
adb shell am instrument --user 10 -w \
  -e class 'com.sleepissue.awakedrive.data.Role1BootDeviceTest#finishAndDisarmWithoutStartingService' \
  -e role1Boot finish -e role1BootRunId "$trial_id" \
  com.sleepissue.awakedrive.test/androidx.test.runner.AndroidJUnitRunner
```

기대값 OK(1 test), arm=false·서비스 시작0이다. 그 뒤 정상 종료/DB close 상태에서 **시작 사본의** `databases/role1-final-20261109-awakedrive_sdk_trip.db`, `shared_prefs/role1-final-20261109-real_trip_monitor.xml`만 복구하고 해시를 대조한다. 새 arm 설정은 제거하고 새 진단은 보존한다. 실패/중단 때도 남은 arm을 해제하고 사용자 데이터 보존을 먼저 마무리한다. 실제 실행 argv는 evidence의 prepare/arm-screen/reboot/finish 명령 JSON에 있다.
