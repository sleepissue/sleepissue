### 변경 범위와 처리 계약

`ScenarioDemoPlayer.pumpLocked()`는 처음 잡은 목표 시각에 머무르지 않고 완전 관측을 전달할 때마다 `DemoClock`의 현재 시각을 다시 읽는다. 차량·내비·전원 세 채널 전달을 마친 뒤에 `nextSample`·전달 수를 함께 증가시킨다. 원본 시각·순서를 바꾸지 않고 남은 원본을 이어서 전달한다.

지속 과부하에서 명령 잠금을 계속 점유하지 않도록 실제 경과25ms를 작업 예산으로 둔다. 먼저 한 원본은 전달하고 완전 관측 경계에서 예산을 확인한다. 이 값은 기술적 soft budget이며 단일 `emit`이 오래 대기하는 경우의 강제 시간상한이 아니다. Pause 처리에서 먼저 시계를 동결하는 순서는 유지한다. 예산 때문에 남은 원본은 `PAUSED`의 후속 `pump()`에서도 동결 시각까지 전달한다. 종료 시각에 도달해도 잔여 원본이 있으면 `PLAYING`·실효0배일 수 있고, 전체 원본을 전달한 뒤에만 무효화·`COMPLETED`로 바꾼다.

debug Activity는 Main scope를 화면·Toast에 유지하고 같은 부모 Job의 `Dispatchers.Default.limitedParallelism(1)` 작업 scope를 Controller에 준다. 초기화·JSON 로드·명령·trace 복사·종료도 작업 dispatcher에서 실행한다. 화면은 `StateFlow`의 불변 snapshot과 그 안의 trace 요약 문자열을 읽으며, 가변 trace 집계에 직접 접근하지 않는다.

검증용 TTL1,000ms·JSON 관측 시각·Hub 중재/발행/원천 Hz 정책은 변경하지 않았다. 실제 SDK 입력 코드·실제 음성 lifecycle 연결을 추가하지 않았다. 장기 버튼 순서와 trace 경로·사용자별 추출 방법은 [사용 가이드의 후속 성능 점검](../setup/ROLE1_DEMO_PLAYER.md#2026-11-05-후속--60배-장기-재생-성능-점검)에 추가했다.
