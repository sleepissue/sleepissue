# 2026-11-10 — SIG_016 호스트·AVD 부하 비교

**유휴 빌드 데몬을 정리해 호스트 메모리 여유는 약2.6→4.9GiB로 늘었지만, 타이머 복귀 지연과 전체1초 초과는 남았다.** 현재 환경의 최대 복귀 지연599ms, 정리 환경619ms다. 이것만으로 호스트 영향이 없거나 SDK가 원인이라고 확정하지 않는다. 특히 두 환경의 CPU 사용률이 거의 같아서 **CPU 저부하 대조 조건은 확보하지 못했다.** 실제로 확보한 비교는 ‘유휴 데몬/메모리 점유를 줄인 정리 환경’이다.

AGENTS.md·최신 현황표·[직전 경계 분리](2026-11-10-sig016-boundaries.md)를 읽고 시작했다. `develop-jdw` / HEAD `b0cfc1eb687b5a134c5d778ca86436f11f9c40e5`와 기존 미커밋을 보존했다. **이번에는 앱/시험 코드·조회 주기·TTL·Clock·AVD/가속/전원 설정을 바꾸지 않았고, 빌드·재설치·커밋·push도 하지 않았다.**

## 자원 비교: CPU 저부하 차이는 만들어지지 않았다

CPU는 `/proc/stat` 차이로 계산했다. 호스트 전체는 논리8CPU 대비 비율, QEMU 프로세스는1CPU=100%다. 범위는 표본 min~max이며 짧은 순간의 최대치를 보장하지 않는다.

| --- | --- | --- |
| 호스트 CPU 전체창 평균 | 52.44% / 52.94% | 52.98% / 52.72% |
| QEMU CPU 표본 | 357.8~400.6% | 362.3~400.0% |
| guest CPU 비유휴 표본 | 86.6~95.2% | 87.4~95.2% |

| 측정창 swap-in/out | in18페이지(72KiB), out0 | in15페이지(60KiB), out0 |

swap 사용량이 크다는 사실과 측정 중 swap I/O를 구분했다. 이번 창에서는 큰 swap-in/out 폭주를 관찰하지 못했다. 반면 AVD CPU/주행뷰·내비/합성 부하는 두 조건에 남았다. 동일 화면과 필수 서비스 조건을 보존하려고 이를 종료하지 않았다. 따라서 **메모리 여유 증가 후에도 재현됨**은 확인했지만, **호스트/AVD CPU·그래픽 영향을 제거한 비교는 미완**이다.

## 보존·재계산·다른 PC

[보존 대조](evidence/2026-11-10-sig016-host/preservation.json): 기존 기기DB/WAL/SHM·prefs·cache **152파일 모두 동일**, 새 진단JSON/stage8개만 추가했다. 기존 저장소 모든 파일/코드/이전 진단은 문서 갱신 전 해시 대조에서 동일했다. 권한·forward·AVD 설정 동일, Console 입력 무조작, 서비스 없음·SDK 소유권 해제·SDK 미연결 화면 복귀를 확인했다. 유휴 빌드 데몬은 요청한 정리 상태로 남겼으며 다음 빌드가 필요할 때 정상 재생성될 수 있다.
