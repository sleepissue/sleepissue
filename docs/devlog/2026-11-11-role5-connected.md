# 2026-11-11 제품 데모 실행 연결

## 변경

제품 런처의 `ProductDemoSession`에 `AndroidDemoExecutionFactory`를 주입했다. SDK 없이 실행하는 기존 기본 세션과 실제 SDK 실행을 연결한 제품 세션을 구분한다.

- 신호는 Player → 수동 VehicleSignalHub 발행 → DemoUiSession 계산을 거친다. 발행 직후 같은 내비·전원 상태를 읽어 비동기 최신값과 섞이지 않게 했다.
- 실행 연결 세션의 단계·질문 재시도·경유지 자동 추가는 실제 서비스와 같은 PolicyInterventionManager·InterventionRouter가 소유한다. 기존 직접 판단 검증 세션은 보존한다.
- 엔진에만 상대 시각 + startEpochMs를 전달하고, 매니저로 돌려주는 판단·안전 사건 시각은 상대 시각으로 복원한다.
- 질문 STARTED/종료·실패·취소를 DemoPlayer로 전달해 질문 동안 1배로 진행한다. 응답 시간과 경유지 유예는 실제 경과 시간을 쓴다.
- 실제 ON_DEVICE TTS/STT·RestAreaRestPort·PleosNaviBridge와 운전자 버튼 대체를 연결했다. 통풍·실제 운행/보상 DB는 데모에서 건드리지 않는다.
- 사용자 지시에 따라 기존 음성 확인 대상·대화 처리 정책을 유지했다. `voice/` 구현은 변경하지 않았다.
- 중지·재로드 때 질문·알람·SDK 부품을 닫고 이전 세션의 늦은 이벤트를 새 세션에 적용하지 않는다.
- 파워냅 Alarming/종료 상태를 기존 ToneNapAlarm 시작·정지에 연결했다.
- 첫 실행/설정에 차속·기어와 Android 13 이상 알림 권한 요청을 추가했다.
- 내비 콜백 수집을 `UNDISPATCHED`로 시작해 addWaypoint 호출 전에 실제 구독을 설치한다. EngineConfig의 반영 확인 한도(현재 12초)는 유지한다. 실패는 성공으로 바꾸지 않고 쉼터 안내로 대체한다.

## 자동 검증

전체 결과: 엔진 346개(기존 결과 재사용), 앱 452개, 실패·오류·skip 0. debug·AndroidTest APK 빌드 성공. 내비 단계 계측 추가 뒤에는 관련 시험만 별도로 실행한다.

추가 JVM 회귀 9개: 실제 10초 유예, 취소 후 자동 추가 없음, 장치 실패와 무응답 구분, 닫힌 세션의 늦은 결과 차단, 질문/경유지 결과 연결, 실행 매니저 경유 normal 0단계와 재로드 정리, drowsy 질문 중 1배 전환, 반영 성공 뒤 후속 화면 지연과 실제 반영 시간 초과의 구분.

## 기기 검증 범위

Pleos Connect v2.1.0/API 34, 소프트웨어 그래픽 콜드 부팅, 현재 사용자 10. 기존 앱 데이터 보존. 기기 시험에서는 마이크 동의만 임시로 끄고 원래 값으로 복구하며 운전자 버튼으로 응답한다. 실제 발화·PCM 대답 시간 시험이나 화면 터치 시험을 대신하지 않는다.

최초 2개 시험: normal 최대0단계·휴식 인증·회복 정상, drowsy 최대3단계·스탬프1개·회복 정상·질문 중1배를 확인했다. 경유지 실제 요청은 STARTED 뒤 TIMED_OUT으로 끝났다. 이 결과를 성공으로 세지 않는다.

최초 파워냅 시험은 출발 전 P단에서 시작해 D단 출발 시 정상 취소됐으므로 알람 확인에 실패했다. 시연 시험을 쉼터 도착 후 선택 시작으로 고쳐 재시험했다. 제품의 ‘정차 중 운전자 선택’ 조건을 쉼터 전용으로 제한하지 않았다. 실제 소리 청취·UI 터치는 이 시험의 범위가 아니다.

내비는 콜백 구독 순서를 고치고, 반영 확인의 설정 한도와 후속 재탐색·화면 열기를 분리했다. 후속 화면 지연이 확인된 추가를 실패로 바꾸지 않는 회귀 시험은 통과했지만 실제 SDK 반영 성공은 아직 확인하지 못했다. 연결·호출·목록 응답 단계 계측으로 원인을 구분한다. 시간 한도를 늘리거나 성공을 꾸미지 않는다.

## 남은 확인

- 실제 발화로 TTS 질문·말소리 시작 시간·STT 의도 전달.
- 내비 경유지 반영 성공. 시간 초과·실패와 안내 대체를 구분한다.
- 실제 서비스 통풍 반영·재조회·휴식 뒤 원복.
- 첫 실행 전체 터치·권한 거절/재허용·실제 주행 제한 리스너.
- 딴짓 기록·분류와 첫 확인 기대 시각의 엔진 담당 자료 대조. 출발 피로 검출 자체는 첫 D단 뒤 약 15분10초 회귀 시험이 통과했다.
- 실제 서비스 설정 입력(연령대·확인 빈도), 실제 모드 버튼 대체는 별도 연결이 필요하다.

최신 통과 결과와 남은 실제 발화 확인은 [11월 12일 점검](2026-11-12-role5-final-checks.md)을 따른다.
