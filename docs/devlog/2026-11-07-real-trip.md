## 구현과 연결

`PlaygroundSignalAdapter → SdkSignalStore → REAL 전용 VehicleSignalHub → PlaygroundTripSession → TripTracker → TripRules/TripStateStore → TripSaveCoordinator → RoomTripRepository → awakedrive_sdk_trip.db`.

- **상태형 신호:** GEAR_SELECTION 공식 ON_CHANGE 계약을 확인했다. [가정] 기어만 1초 재조회/3초 확인 lease를 사용하며 다른 연속 신호의 TTL 3초는 늘리지 않았다. `observedAtMs/nativeMs`·`receivedAtElapsedMs/receivedMs`·`stateConfirmedAtElapsedMs/confirmedMs`를 구분한다. 같은 상태 재조회는 콜백/센서 관측 순번/원천 변경·수신 시각을 증가시키지 않는다. Hub도 확인 메타데이터만 갱신한다.
- **오류/세션:** 부분 갱신에서 빠진 필드는 유지하고 명시 null/미수신/오류는 무효화한다. 기어 조회/구독 실패·권한 상실·CarService 해제는 lease와 값을 끊고 늦은 배송을 차단한다. 어댑터 단회 시작·중복 ready 무시·Car 연결 세대·Controller 입력 세대와 Hub 순번으로 중복/이전 세션 입력을 막는다.
- **전원:** 실제 전원 API·권한·의미는 미확인이므로 연결하지 않았다. UNKNOWN/앱 종료를 OFF로 만들지 않는다. D/P 기어로 기존 운행 규칙을 계산하며 실제 시동 OFF 규칙까지 기기 연결 완료한 것은 아니다.
- **운행/시계:** 기존 첫 D·P·재출발, [가정] V03_RETROACTIVE/EXCLUDE, 정밀 ms·24시간 구간 규칙을 재사용한다. 운행 시각은 세션 시작 날짜 + 실제 단조 경과(WALL_EPOCH), 저장 타이머는 실제 elapsed 10초다. DEMO/수동 시계·상태·DB는 공유하지 않는다.
- **저장/복원:** 기존 Room 스키마 1·운전 구간·정밀 정차·수동 개입 owner 형식을 유지한다. REAL은 nullable 입력만 담는 `REAL_TRIP_V1` owner를 사용해 가짜 개입 평가를 만들지 않는다. 저장/실패/성공 횟수/논리·날짜·elapsed 시각과 복원 전후 ID·시간·최근 누적을 화면·진단에 표시한다. 늦은 과거 저장 요청은 새 checkpoint를 덮지 않는다.
- **복원 의미:** 원본 저장 snapshot을 검증/보존하고 활성 Tracker는 저장 시점에서 입력을 끊어 UNKNOWN으로 재개한다. 닫힌 시간은 운전·정차·OFF에 더하지 않는다. 새 P를 받으면 정차 증명은 새 시각부터다. DB 읽기/검증 실패나 날짜 역행은 자동 저장 중지·원본 보존이다.
- **조립 위치:** 새 debug `Playground SDK 운행·Room` 화면이 실제 경로를 실행한다. 최종 서비스나 다른 담당 판단/음성/쉼터/휴식의 제품 통합은 아니다. 기존 SDK 원시 진단 화면도 유지했다.

## 기기에서 발견한 문제와 수정

초기 연결에서 Vehicle2.3.2의 `checkHvacTemperatureCurrentCapabilities` 내부 Kotlin reflection이 main을 막아 FocusEvent ANR이 발생했다. [main 스택](evidence/2026-11-07-real-trip/initial-anr-main.txt)에 근거해 Vehicle capability 초기 확인을 IO로 이동하고 상태/콜백은 기존 handler로 전달했다. 수정 후 관찰 구간에서 새 ANR은 확인되지 않았다. 전체 호스트/플랫폼 지연에 대한 보증은 아니다.

초기 화면 스레드 소비에서는 UI 갱신 중 Hub 순번 누락이 생겨 보수적 UNKNOWN 분리가 정차 근거를 끊었다. 새 SDK 운행 collector를 Default로 분리하고 짧은 상태 갱신만 동기화했다. DB I/O는 그 잠금 밖에서 실행한다. 최종 D→P→D 측정 구간의 Controller에는 순번 누락 기록이 없었다. 전역 Hub/데모/60배 전달 로직을 다시 설계하거나 성능 조정하지 않았다. 누락이 실제 발생하면 여전히 마지막 확정 프레임에서 끊으며 장애 발견 시각까지 소급 합산하지 않는다.

초기 실패/중간 입력 캡처(01~06)와 최종 APK 캡처(10 이후)를 구분해 보존한다. 첫 자동 버튼 시험의 uiautomator dump는 idle 확인 실패로 중단됐다. P/0 화면을 캡처해 실제 표시된 버튼 좌표로 저장/진단/연결을 눌렀으며 OS 주행 제한을 해제하지 않았다.
