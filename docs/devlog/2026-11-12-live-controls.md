# 2026-11-12 실제 모드 설정·동승자 버튼 연결

현재 기능 기획서 4-4·5-3·5-4·6·8장의 설정·확인 규칙과 기존 인계 문서를 대조했다. `feat/ui-role5-rehearsal`에서 누락된 실제 서비스 연결을 보완했다. 여기서 실제 모드는 Playground SDK·Virtual Console 입력을 뜻하며 물리 차량 검증이 아니다.

## 연결 내용

- `LiveDriveUiSession`의 설정 입력을 `MonitoringPipeline.updateSettings`로 전달한다. 서비스 생성 때 저장된 설정도 읽는다.
- 연령대는 기존 데모 매핑(청년→TWENTIES, 중년→THIRTIES_FORTIES, 고령→FIFTIES_PLUS, 미설정→null)을 재사용한다. `FatigueAssessmentRunner`가 프레임 처리와 같은 Mutex로 설정을 반영한다. Mutex는 여러 코루틴이 엔진을 동시에 바꾸지 않도록 순서를 지키는 잠금이다.
- 연령대는 조향 판단의 맥락·취약 시간대와 예보 입력에 들어간다. 변경 시 기존 CONDITION_INPUT 경로로 예보를 다시 계산한다.
- 확인 빈도는 새 `FrequentChecksChanged` 입력으로 기존 개입 매니저에 전달한다. 보조 주행 중 자주 확인은 EngineConfig의 위험 확인 간격(10분), 기본은 일반 간격(20분)이다. 기본으로 바꿔도 취약 시간대·민감 모드·장시간 운전의 10분 확인은 유지한다.
- 동승자 버튼은 동승자 확인 설정이 켜져 있고 음성 안내가 시작된 졸음 확인 요청이 진행 중일 때만 같은 요청 ID·문맥으로 답한다. ‘쉬어 가요’는 REST, ‘괜찮아요’는 OK, 응답 채널은 PASSENGER_BUTTON이다. 버튼으로 음성 응답 시간을 만들지 않는다.
- 확인 요청 없음·질문 시작 전·이미 처리된 요청·경유지 동의·회복 확인에는 동승자 버튼으로 답할 수 없다. 음성 질문은 기존 사용자 지시대로 항상 운전자에게 하는 정책을 유지한다.
- 버튼 응답 뒤 인식을 취소하고, 늦게 완료되는 TTS 콜백이 인식을 다시 시작하지 않도록 확인 흐름의 세대를 무효화한다. `VoiceCheckSession` 계약을 분리해 기기 구현과 JVM 시험이 같은 시작·취소 경계를 사용한다.

## 기기 검증 후속

Pleos v2.1.0을 기존 데이터 유지·소프트웨어 그래픽·콜드 부팅으로 실행했다. `LiveControlsDeviceTest`는 실제 감시 서비스와 제품 화면을 사용하고 확인 요청 발생만 합성 점수로 요청한다. P단·0km/h에서 시험했으며 실제 조향 신호로 졸음을 검출한 시험은 아니다. 마이크 권한은 시험 동안 거부하고 직접 발화를 수행하지 않았다.

- 실제 설정 화면에서 중년 선택 → 서비스 엔진의 THIRTIES_FORTIES 반영, 확인 빈도 저장, 동승자 확인 끄기·켜기를 확인했다.
- 감시를 중지·재시작해 새 파이프라인이 저장된 연령대를 읽는지 확인했다. OS 프로세스 종료·기기 재부팅 복원 시험과 구분한다.
- 진행 중인 확인에서도 동승자 설정을 끄면 응답이 거절되고 다시 켜면 응답할 수 있었다.
- ‘괜찮아요’ 클릭 → 결과 전달·중복 거절, 새 확인에서 ‘쉬어 가요’ 클릭 → CHECK_RESULT 사유의 3단계 전환을 확인했다.
- 실제 서비스의 마이크 가능 여부가 true로 고정되어 있어 동의·권한을 확인하도록 보완했다. 마이크 대체 버튼 요청도 STARTED로 전달해 같은 확인 요청에 응답할 수 있게 했다.
- 최초 시험은 출발 준비 화면을 마치는 절차가 누락돼 버튼 탐색 시간 초과였다. 시험 조작을 고친 재시험과 설정 해제 차단까지 강화한 최종 시험은 각각 OK (1 test)다. 실패 기록도 함께 보존한다.
- 최종 시험 42.738초. 원본은 [기기 증거](evidence/2026-11-12-live-controls/final/result.json), [실행 로그](evidence/2026-11-12-live-controls/final/instrumentation.log), [권한·감시 복구 확인](evidence/2026-11-12-live-controls/final/post-check.json)에 있다. 마지막 화면 캡처는 비동기 UI 갱신 전일 수 있으므로 단계 전환 근거는 테스트의 서비스 상태 assertion과 결과 파일이다.

재현은 제품·시험 APK 설치와 `adb forward tcp:8088 tcp:8088` 뒤 저장소 루트에서 `python3 tools/verify_role5_live_controls.py`를 실행한다. 도구는 기존 실제 감시가 실행 중이면 중단하며, 권한·가상 차량 조작 값을 복구한다. 시험은 설정과 첫 실행 안내 값을 원복하고 자신이 시작한 감시를 중지한다.

## 남은 항목

직접 발화 리허설은 사용자가 명시적으로 진행하라고 할 때까지 보류한다. 실제 ‘네’·‘응’의 인식 의도·목소리 시작 시간과 알람 청취는 확인하지 않았다.

대화 감지 입력 `speechDetected=false`, 실제 서비스의 운전자 버튼 표시·응답 연결, 화면 밖 마이크 서비스 범위는 이번 검증과 별도다. 기존 미추적 시나리오·백업 파일과 도구는 보존했다.
