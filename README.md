# 깨어있는 드라이브 (AwakeDrive)

졸음운전을 경고에서 끝내지 않고, 운전대 조향 패턴으로 졸음 징후를 찾아 말로 확인한 뒤 앞쪽 졸음쉼터를 내비게이션 경유지로 넣고, 휴식을 차량 데이터로 자동 인증해 보상까지 이어 주는 Pleos Connect 앱입니다.

> 본 앱은 졸음을 진단하지 않습니다. 차량 기본 경고를 대체하지 않는 위험 신호 알림·대응 보조 서비스입니다.

## APK 파일 위치

- `apk/졸음있슈_AwakeDrive_release.apk` (release 빌드, 서명 완료)

## 테스트 환경 및 필요한 설정

| 항목 | 값 |
| --- | --- |
| 에뮬레이터 | Pleos Connect Emulator **v2.1.0** (Android 14, API 34, Automotive) |
| 화면 규격 | 2560x1440, 160dpi (가로형) |
| 에뮬레이터 설정 | RAM 4 GB, **Cold Boot** 로 시작 |
| 개발 도구 | Android Studio, Kotlin, Jetpack Compose, minSdk 28 |
| Pleos SDK | Vehicle 2.3.2, NaviHelper 3.0.5, TextToSpeech 3.3.1, SpeechToText 3.3.1 |
| Virtual Console | `adb forward tcp:8088 tcp:8088` 뒤 브라우저에서 `http://127.0.0.1:8088` |

필요한 설정

1. 에뮬레이터에 CRN을 주입합니다(Pleos Playground에서 발급받은 값, 에뮬레이터마다 1회). 방법은 `tools/inject_crn.sh` 와 `.env.example` 을 참고합니다. CRN은 저장소에 포함하지 않습니다.
2. 앱 첫 실행 때 마이크·알림 권한을 허용합니다.
3. 음성으로 대답하려면 앱 **설정 → 마이크 사용 동의**를 켜고, 에뮬레이터 설정(⋯ → Microphone)에서 호스트 마이크 사용을 켭니다. 켜지 않으면 화면 버튼으로 대답합니다.
4. 운전석 통풍 자동 켜기를 보려면 앱 **설정 → 통풍 동의**를 켭니다.

## 실행 방법

### 1) APK 설치

```bash
adb install -r apk/졸음있슈_AwakeDrive_release.apk
```

설치 뒤 에뮬레이터의 앱 목록에서 **AwakeDrive** 를 실행합니다.

### 2) 데모 시나리오 재생 (권장)

에뮬레이터에서는 실제 졸음 조향을 만들 수 없어, 0.1초 간격으로 기록한 시나리오를 실제 신호와 같은 통로로 재생합니다. 재생 중에는 화면에 **데모 재생 중**이 표시됩니다.

1. Virtual Console의 기어를 **P단**으로 둡니다. (D단에서는 플랫폼 홈 화면이 앱 화면을 가립니다.)
2. 앱 아래쪽 탭에서 **데모**를 누릅니다.
3. 배속을 고르고 시나리오를 누르면 바로 재생됩니다: **정상 / 딴짓 / 졸음 / 대화 / 보조 주행 / 출발 피로**
4. **졸음** 시나리오의 흐름: 위험 점수 상승 → 음성 확인 질문 → 느린 대답 2회 또는 무응답 → 3단계 경고 → 쉼터 경유지 제안 → 쉼터 정차 15분 → 휴식 인증·스탬프

실제 감시(운전 시작)가 켜져 있으면 데모가 열리지 않습니다. 알림의 **감시 중지**를 누른 뒤 데모를 엽니다.

### 3) 실제 차량 신호 연동 확인

앱에서 감시를 시작한 뒤 Virtual Console에서 좌석 착석, 크루즈, 방향지시등, 브레이크, 통풍을 바꾸면 앱이 값을 받아 반영합니다.

### 4) 소스에서 빌드

```bash
cd src/android
./gradlew :engine:test :app:testDebugUnitTest   # 자동 시험
./gradlew assembleRelease                        # release 빌드
```

Android Studio에서는 `src/android` 폴더를 엽니다. Pleos Maven 저장소(`https://nexus-playground.pleos.ai/repository/maven-releases/`)에 접근할 수 있어야 합니다.

## 주요 기능

- 조향 패턴 감지: 시속 60 km 이상·D단 등 조건을 통과한 구간에서 미세 수정·큰 수정·멈춤 뒤 급조향 3개 지표로 위험 점수(0~100) 계산
- 딴짓·졸음 구분: 이상이 이어지는 모양(추세형·튐형)과 음성 확인 결과로 구분
- 음성 확인: 신호음 뒤 대답이 시작될 때까지의 시간으로 판정(느림·무응답)
- 0~3단계 개입: 안내 → 확인(+운전석 통풍) → 쉼터 경유지 제안·자동 추가
- 휴식 자동 인증·보상: 쉼터 반경 150 m + P단(또는 전원 꺼짐) + 15분
- 파워냅 알람, 출발 전 예보, 크루즈 기반 보조 주행 모드

## 구조

```
src/android/engine/   판단 로직 (Android에 의존하지 않는 순수 Kotlin, 자동 시험 359개)
src/android/app/      SDK 래퍼·신호 수집·음성·내비·휴식·화면 (자동 시험 522개)
data/scenarios/       데모 시나리오 6종 (각 45분, 10 Hz)
data/rest_areas/      한국도로공사 졸음쉼터 253곳 + 휴게소 215곳
docs/                 기획서·설계·검증 기록
```

## 알려진 한계

- 실제 조향 신호는 판단에 넣지 않습니다. 공개 SDK의 조향 값이 앞바퀴 각도로 설명되어 있고 기본 1초 간격이라, 의미가 확인되기 전에는 추측한 값으로 판단하지 않습니다. 조향 판단은 데모 시나리오 재생으로 확인합니다.
- 에뮬레이터에서 D단을 넣으면 플랫폼 홈 화면이 앱 화면을 가립니다. 앱과 음성은 계속 동작합니다.
- 데모 재생은 실제 내비게이션 경로와 통풍을 바꾸지 않고 결과를 앱 화면에 표시합니다. 실제 경유지 추가와 통풍 제어는 실제 신호 경로에서 동작합니다.
- 음성 확인은 앱 화면이 떠 있을 때만 마이크를 씁니다.
- 대화 감지와 동승자 음성 확인, 개인 기준선(평소의 나), 주간 리포트는 다음 단계 범위입니다.
